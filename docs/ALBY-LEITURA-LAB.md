# Validação Alby somente leitura — LXC lab 121 (21/10/2026)

**Escopo aprovado:** usar apenas o token novo depositado pelo usuário no arquivo local root 0600 para GET autenticado; sem LNbits com Alby, invoice, pagamento, transferência ou mudança de carteira. O token exposto anteriormente foi informado como revogado pelo usuário; esta sessão não o acessou. Resultados abaixo são sanitizados: nenhum token, hash, cabeçalho de autorização, corpo JSON, identificador de usuário ou lista de faturas aparece neste documento.

## Proteções executadas

- Verificados **somente metadados**: `/opt/tcc-ln-lab/secrets` é diretório root:root 0700; `/opt/tcc-ln-lab/secrets/alby-access-token` é arquivo regular root:root 0600, não symlink. Arquivo não foi copiado, hasheado nem lido pelo LXC dev.
- Scripts locais sem segredo: `lab/alby_lab_run.sh`, `lab/alby_connect_proxy.py`, `lab/alby_readonly_client.py`. Cópias no LXC 121 em `/opt/tcc-ln-lab/`. Nenhum deles lê token no proxy; o cliente o abre **apenas após** provas de egress e somente em memória. Não usa env, argv ou logs para transmitir credencial; exceções do cliente são suprimidas. Cuidado: root no LXC e software privilegiado ainda podem ler memória/arquivo; não existe garantia absoluta contra comprometimento do host.
- LNbits permaneceu **parado** e launcher `/opt/tcc-ln-lab/run.sh` continuou `VoidWallet`. O cliente efêmero não instancia `AlbyWallet` nem chama a API do gateway.
- `ip netns` temporária `tcc-alby-readonly`, veth `172.31.252.2` → host `172.31.252.1`, sem rota default nem interface externa. Dentro dela: nft `output` e `input` **policy drop**, saída aceita só TCP ao proxy `172.31.252.1:18765`; IPv6 não liberado. No host do **lab**, tabela nft temporária `tcc_alby_host` nega input não autorizado e forward da veth, sem alterar regras globais de SSH. O proxy não contém credenciais, atende CONNECT exatamente `api.getalby.com:443` com Host idêntico, rejeita qualquer outro CONNECT e valida **SNI idêntico** antes de abrir socket externo; resolve somente IP público para esse hostname. Embora os IPs da Cloudflare sejam compartilhados, o proxy não oferece passthrough de outros hostnames via CONNECT ou SNI. O cliente usa TLS com CA do sistema e verificação do certificado contra `api.getalby.com`, sem redirects; endpoints só GET allowlisted.
- **Provas negativas antes de abrir o token:** sockets diretos IPv4 para `1.1.1.1`, `10.10.10.102`, `10.10.10.121`, `192.168.3.1`, `169.254.169.254`, `127.0.0.1` falharam; socket IPv6 público falhou; CONNECT para `example.com`, IP privado, gateway e IP público arbitrário foram negados; CONNECT autorizado com SNI `example.com` não estabeleceu TLS. Isso verifica o canal de saída do processo de consulta, não um firewall permanente para todo o LXC. O proxy também compara peer à interface veth esperada. Limite: SNI é validado antes do upstream, não é MITM; o certificado TLS final é validado no cliente.

## Respostas reais, sem dados pessoais

- `GET https://api.getalby.com/balance`: **HTTP 200**, resposta JSON com `unit=sat`, saldo agregado observado **0 sat**.
- `GET https://api.getalby.com/invoices/incoming?items=1&page=1`: **HTTP 200**, resposta JSON é uma lista; conteúdo/contagem não registrados nem exibidos. O GET demonstra permissão de consulta nesta API legada, mas **não prova ausência** de escopos adicionais (`payments:send`, `invoices:create`). Essa ausência foi declarada pelo usuário na UI; nenhum POST foi feito para testá-la. Não foi necessário consultar `/oauth/token/introspect` para o objetivo autorizado, e esse endpoint não foi usado.
- A Alby Wallet API citada no contrato LNbits 1.6.2 está marcada **deprecated** na documentação do provedor; dois GETs bem-sucedidos não comprovam suporte futuro ou segurança para emissão.

## Rollback e estado final

O launcher temporário tem trap que mata o proxy e remove namespace, veth e tabela nft temporária. Depois da execução foram conferidos: `ip netns list` vazio para esta namespace, `nft list tables` com apenas a tabela preexistente `inet filter`, host SSH ainda em `*:22`, nenhum processo LNbits ativo, `run.sh` preservado em `VoidWallet`. O arquivo root 0600 ficou no caminho original sem cópia. **Em encerramento abrupto que impeça o trap (SIGKILL ou reboot parcial), antes de qualquer nova execução, no lab apenas:** parar o processo `alby_connect_proxy.py` caso exista; executar `ip netns del tcc-alby-readonly` se presente, `ip link del tcc-a-host` se presente e `nft delete table inet tcc_alby_host` se presente; verificar `nft list tables`, `ip netns list`, `ss -lnt` e `run.sh`. Não remover tabelas, rotas ou serviços de outros LXCs. Não repetir GET sem autorização operacional renovada se houver divergência.

**Limites:** nenhuma operação com fundos ou invoice; saldo observado é fotografia, não garantia futura. Permissão de leitura comprovada somente para os dois GETs executados, não para outros endpoints nem para LNbits usando token. O sandbox LNbits continua sem egress e sem backend Alby. Integrar o backend real exige mitigação separada do segredo via env/proc/log, política de permissões e deduplicação de emissão; esta etapa não a autoriza.
